Redesign the entire Snitch website UI. Snitch is a clothing brand positioned 
in the middle of premium and streetwear — considered, elevated pieces with 
real edge, not luxury-minimalist and not loud/logo-driven streetwear either. 
Find the tension between those two poles rather than defaulting to one.

CREATIVE FREEDOM
You have full creative license on fonts, imagery, color, layout, and motion 
direction. Nothing about the current visual design (a light editorial theme 
with Archivo/Fraunces typography, a specific bordered-cell navbar, etc.) is 
locked in — treat it as one possible starting point, not a constraint. 
Propose a direction that genuinely earns "premium x streetwear" rather than 
reusing whatever's already there by default.

---

CRITICAL: DO NOT BREAK EXISTING FUNCTIONALITY

All application logic, state management, API contracts, and data flow are 
already fully implemented and working. This is a visual/UI redesign only — 
every workflow below must continue working exactly as-is after the redesign. 
Never change data shapes, API calls, routing logic, or business logic to 
achieve a visual effect; only restyle and restructure the presentation layer 
around them.

AUTH
- Access + refresh JWT tokens in httpOnly cookies, with automatic 
  refresh-on-401 via an axios interceptor (src/lib/axios.js) — never move 
  tokens into localStorage or any client-readable storage to "simplify" a 
  redesign.
- AuthContext (useAuth()) exposes { user, login, register, logout, loading } 
  — SSR-hydrated on first load via a server-side token check in layout.js. 
  Any redesigned auth pages/forms must keep calling these same functions.
- Admin-only UI (e.g. an "Admin" nav link) must stay conditioned on 
  user?.role === "admin" — never remove this check for a cleaner-looking 
  nav.

CART
- Works for both guests (via a guestCartId cookie) and logged-in users, 
  merged automatically on login. Cart state lives in Redux Toolkit 
  (src/store/cartSlice.js) — fetchCart, addToCart, updateCartItem, 
  removeCartItem are async thunks calling real API routes.
- Pricing/totals are ALWAYS server-computed and returned by the API — never 
  calculate or display a total the frontend derived itself.
- The navbar's cart badge count must keep dispatching fetchCart() on mount 
  so it's correct immediately on page load, not just after visiting /cart.

PRODUCTS
- Products have variants (color, images, sizes with per-size stock and 
  optional price override) — the product detail page's color/size selection 
  UI must keep reading from this real variant/size data structure, not be 
  simplified into flat "options."
- The public catalog page (/products) supports department/search/sort/page 
  as URL query params, driving a real API call each time — a redesign of 
  filters/sort UI must keep writing to and reading from the same URL params, 
  since this is what makes filtered views shareable/bookmarkable.
- Product images are objects ({ url, fileId }), not plain strings — any 
  redesigned image component must keep reading .url, not assume a string.

ADMIN
- Full CRUD (create/list/update/delete) exists for products, gated by role 
  check on both frontend (AdminLayout redirect) and backend (every admin 
  API route independently re-checks role — this is defense in depth, not 
  redundant, and must not be "simplified" away on either side).
- Image upload (ImageUploader component) uploads immediately on file 
  selection (not deferred to form submit) and supports drag-to-reorder — 
  a redesigned admin form UI must preserve this immediate-upload behavior 
  and the reordering interaction, not just its current visual appearance.

PAGE TRANSITIONS & MOTION INFRASTRUCTURE
- TransitionProvider + TransitionLink handle all internal navigation via a 
  full-screen curtain cover/reveal sequence — every internal link in the 
  app uses TransitionLink, not next/link. A redesign can change the 
  curtain's visual content and animation style entirely, but must keep 
  using this same navigation mechanism (navigateWithTransition), not 
  reintroduce next/link for internal navigation.
- Preloader plays once on first load, signals completion via AppReadyContext 
  (useAppReady() → { ready }) — any homepage entrance animations (hero text, 
  etc.) must stay gated on ready being true, so they never play before the 
  preloader clears.
- CustomCursor (dot that expands on hover) is driven by CursorContext's 
  setVariant("view" | "default") — redesigned interactive elements 
  (product cards, department tiles, etc.) should keep calling setVariant 
  on hover/focus/blur to stay integrated with this system, not implement 
  their own separate cursor logic.

CURRENT PAGE/COMPONENT INVENTORY (all functional, all restylable)
- Navbar, Hero, BrandStatement, ShopByDepartment, product grid, JournalTeaser, 
  Footer — homepage sections, in this order
- /products (catalog with filters), /products/[slug] (detail with gallery, 
  variant/size picker, add to cart)
- /cart, /login, /register
- /journal, /journal/[slug] (static content, journalPosts.js data file)
- /admin, /admin/products/new, /admin/products/[id]/edit (dashboard + forms)
